## 0. Conventions that apply to every section below

### 0.1 Key and modifier mapping macOS -> Windows
| macOS | Windows | Used for |
|---|---|---|
| ⌘ in an *app-level* shortcut (⌘Q ⌘W ⌘X ⌘V ⌘C ⌘Tab) | Ctrl (Alt for Tab/F4 where Windows has its own convention) | quit/close protection, cut and paste, switcher |
| ⌘ in a *pure modifier chord* (super key, window gesture) | Win (⊞) | super key output, window drag gesture |
| ⌥ | Alt | everywhere |
| ⌃ | Ctrl | everywhere |
| ⇧ | Shift | everywhere |
| global "⌃⌥⌘ + letter" layer | Ctrl+Alt+Win + letter (⊞) | all "free layer" defaults |
| ⌘Tab / ⌘` | Alt+Tab / Alt+` | switcher |
| Return / Delete | Enter / Backspace(Delete) | |
Rule of thumb: *global hotkeys and modifier chords keep Vorssaint's modifier layers 1:1 with ⌘ = Win* (so the many `⌃⌥⌘+letter` defaults stay unique and collision-free: e.g. Clipboard ⌃⌥⌘V = Ctrl+Alt+Win+V and Paste-plain ⇧⌥⌘V = Shift+Alt+Win+V are different chords); *shortcuts that Vorssaint intercepts inside the frontmost app* use the Windows convention (⌘Q -> Alt+F4, ⌘W -> Ctrl+W, ⌘X/⌘V -> Ctrl+X/Ctrl+V, ⌘Tab -> Alt+Tab). Hotkeys are registered with `RegisterHotKey` (MOD_WIN allowed; a Win+Ctrl+Alt+letter chord is not reserved by Windows) or through the low-level keyboard hook when they must also swallow a system chord. WinKnife's current defaults (Ctrl+Alt+<letter>, Ctrl+Alt+Shift+<letter>) predate this mapping and must be migrated to it; user-customised values are kept.
Key-cap glyph rendering: render modifiers as words in caps ("Ctrl", "Alt", "Shift", "Win" with the ⊞ glyph U+229E or Segoe `E782`), not Mac glyphs. Wherever a string below contains ⌘/⌥/⌃/⇧ replace by the Windows spelling.
Shortcut recording rule (string `shortcutInvalid`): "Use at least Control, Option or Command with a key." -> "Use at least Ctrl, Alt or Win with a key." (function keys alone are allowed, as in Vorssaint's F2 default). Other shared strings: `shortcutRecording` "Press the new shortcut", `shortcutReset` "Reset", `shortcutNone` "None", `shortcutClear` "Remove shortcut", `shortcutPressKeys` "Press keys", `shortcutEscapeHint` "Escape cancels.", `shortcutDeleteHint` "Delete clears.", `shortcutNotCaptured` "Nothing was captured. Windows or another app already uses that combination. Try another one.", `shortcutConflictFormat` "This shortcut is already used by %@.", `shortcutUnavailable` "Windows rejected this shortcut. Choose another one." (RegisterHotKey returned false).
"Take over from macOS" offer (`shortcutTakeOverOffer` etc.) has no Windows equivalent for RegisterHotKey-style shortcuts except the few reserved Win-combos; implement only for the Switcher (Alt+Tab replacement, see 1.1). Other takeovers are not needed: a low-level keyboard hook (WH_KEYBOARD_LL) sees keys before the shell, so Win+<key> combos can be swallowed there.

### 0.2 Platform permissions
Windows has no Accessibility / Screen-Recording / Automation grants. Rules for every `PermissionRow(kind: .accessibility|.screenRecording)` in the Mac UI:
- Accessibility -> never shown as "missing". Hooks (`SetWindowsHookEx` WH_KEYBOARD_LL / WH_MOUSE_LL), UI Automation, `SetWinEventHook` and `SendInput` need no grant.
- The only real limitation is UIPI: a non-elevated WinKnife cannot move, close, read or send input to windows of elevated (admin) apps. Replace the "Permission required" card by an optional card **"Administrator access"** (title `permissionRequired` = "Permission required" kept) with row text: "Some windows belong to apps running as administrator. Run WinKnife as administrator to control them." and a button "Restart as administrator" (ShellExecute verb `runas`). Show it only while one of the enabled features needs it AND `IsUserAnAdmin()==false` AND an elevated foreground window has been seen. Never block the feature.
- Screen Recording -> never needed: previews use DWM thumbnails (`DwmRegisterThumbnail`) and, for minimized/cloaked windows, a cached bitmap from `PrintWindow(PW_RENDERFULLCONTENT)` or Windows.Graphics.Capture (borderless where supported). No card.
- Notifications -> Windows toast (`ToastNotificationManager`), always allowed; if the user disabled them the existing string `notificationsDenied` is shown with a link to `ms-settings:notifications`.
- Secure input (`SecureInputMonitor`, "Secure input is on"): no Windows equivalent. The password-field case is detected per field with UI Automation `IsPassword`; snippets/switcher simply skip that field. Hide every `SecureInputRow`.
- Launch at login: `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` (existing `AutoStart.cs`).

### 0.3 Shared settings-page chrome (Mac `SettingsView` pages that are `ScrollView + VStack(spacing 20)`)
All my "card" pages (Switcher, Dock, Mouse, Energy) use: page scroll area `maxWidth 760`, centered, padding 22. Header = `title2 bold` page title, then 5pt gap, then `callout` secondary description (wraps). Cards are `SettingsCard`: padding 16, corner radius 16 (continuous), background `quaternary 35%` (Windows: `CardBackground` = Text colour at ~6% alpha over window background; dark: #FFFFFF 6%, light: #000000 4%), inner VStack spacing 13, optional `headline` (semibold 15) card title.
`SettingsRow`: HStack spacing 12: icon tile 26x26 radius 7, bg accent 12%, glyph 12pt semibold in accent colour; title (body 13pt) + optional capsule badge (8pt bold white on accent, padding 5x1); caption below (`caption` 11pt, secondary, wraps); `Spacer(min 12)`; trailing accessory (switch, picker, slider...). Text inset for children indented under a row = 26+12 = 38pt. A `Divider` is a 1pt separator line at 12% text colour.
"Form" pages (Window Layout, Clipboard, Cut & paste, Auto quit, Shelf, Super key, Quit protection, Key debounce, URL cleaner, Text snippets) use `Form.formStyle(.grouped)`: sections are inset rounded groups, section header 11pt semibold secondary uppercase-free text, toggle rows 13pt with the caption (`caption` 11pt secondary) directly under the toggle inside the same group. On Windows render both with the same `SettingsCard` visual language (rounded group, 16pt padding, 12pt row gap); the only difference is that "Form" sections are titled with a small header above the group instead of `headline` inside it.
Toggles are Fluent switches (width 40, height 20) everywhere ("labelsHidden" - the label is the row title). Chip groups ("chipRow"): height 28, horizontal padding 10, corner radius 8, font 11 medium; selected = accent 12% fill + 1pt accent 70% border + accent text; unselected = text 6% fill, no border. Gap 8, wraps (FlowLayout). Segmented pickers = Fluent segmented control. "Menu" pickers = ComboBox.
"Active now" status badge (`activeBadge`): capsule, green 12% fill, `checkmark.circle.fill` glyph (Segoe `E73E`) + green 11pt text, shown only while the service really runs.
Disclosure groups ("More options") = Expander, header `subheadline medium`.
**App lists** (every "Add an app..." list: Mouse exceptions, Clipboard ignored apps, Switcher rules, Window layout ignore, Preview pause, Maximizer exceptions, Auto quit, Quit protection exceptions, Shelf, Keep awake apps) share one component `AppBundleList`: an Expander whose header is `[title] ........ [count]` (count secondary, monospaced digit, hidden when 0; expanded initially iff the list is non-empty). Body: one row per app = 18x18 icon, name (+ secondary caption line with the folder path, head-truncated, when known), optional trailing accessory (e.g. a picker), then `minus.circle.fill` (Segoe `E738` "Remove"/ or `EB90`) button in secondary colour with accessibility label = `removeButton` "Remove". Under the rows a small button `+ Add an app...` (Segoe `E710`), then the list caption (`caption` secondary). Picking an app opens an "App picker" dialog: searchable list of running apps and installed apps (Start Menu shortcuts / App Paths / UWP via `Get-StartApps` equivalent), with a "Browse..." button for any `.exe`. App identity on Windows = lowercase process image name (`chrome.exe`) for Win32, or the package family name for UWP (`Microsoft.WindowsTerminal_8wekyb3d8bbwe`) - this replaces macOS bundle ids; store as strings, case-insensitive compare. Exceptions that name a full path are also accepted (Mac `acceptsExecutables`).

### 0.4 Floating overlays (HUDs/panels)
Vorssaint overlays are borderless non-activating panels with `HUDBackdrop` (frosted material) + 1pt `white 12%` border and a drop shadow. On Windows: borderless topmost `WS_EX_NOACTIVATE | WS_EX_TOOLWINDOW` WPF window, Mica/Acrylic backdrop (`DwmSetWindowAttribute DWMWA_SYSTEMBACKDROP_TYPE = 3 (transient/acrylic)` on Win11, fallback to a 92% opaque dark/light fill), rounded with `DWMWA_WINDOW_CORNER_PREFERENCE = round`, border 1pt white 12%. Light/dark follow the app theme. They must appear on every virtual desktop (`VirtualDesktopManager` is not needed: pin with `IVirtualDesktopPinnedApps` is undocumented; instead create them topmost + re-show on `VirtualDesktopChanged`; acceptable fallback).

### A1.2 Overlay (`SwitcherView`, `AppSwitcher`)
Behaviour: a non-activating topmost panel, on every desktop; **opens only after `switcherAppearanceDelay`** (default 100 ms) while the shortcut modifier is held; releasing the modifier before it appears commits silently (flick toggles to the previous window = "second most recent"). The modifier-held session:
- Shortcut key repeated (Tab) = next; `Shift` (press) or `Shift+Tab` or `←` = previous (the Tab that belongs to the same chord as the Shift press must not step twice; recognised by a ~short time window); `→` next; `↑/↓` jump a row in the grid (no wrap; in icon-row layout the Windows shortcut walks the selected app's windows); mouse wheel scrolls/moves; `Enter` commits; `Esc` cancels (and click outside cancels *before* the click passes through); release of the modifier commits; click on a card commits; middle-click on a card closes that window; `W` closes the highlighted window (panel stays open and moves on; closing windows stay listed until really gone, are never raised on release; given back if still alive after ~closing time); `Q` quits the highlighted app (WM_CLOSE to all its top-level windows, then keeps listing them as closing; reappear if still running); letters otherwise start the search field (typed text filters titles and app names, `Backspace` edits, `S` pins search open: while pinned, releasing the modifier does not commit). If "Quit & close protection" protects W/Q for that app the switcher itself asks for the second press ("Press %@ again to quit") because the global tap yields while the session is open.
- Hover selection is ignored until the pointer actually moves after opening.
- Re-fits the panel when an app quits mid-session.
- Secure-input handling: none on Windows.
Data per entry (`SwitcherItem`): window handle, process, app icon, app name, title, minimized, fullscreen, on other desktop, "app entry" (no window). `displaySubtitle` = app name shown under the title only when the title differs (case-insensitive) from the app name. Status badges (top-left of a card, 20x18 radius 6, black 46%, white 90% glyph 9pt bold): minimized (Segoe `E921`), fullscreen (`E740`), other desktop (`E7C4`).
Window order = most-recently-used (`WindowUseTracker`: foreground-change WinEvents `EVENT_SYSTEM_FOREGROUND` build the MRU list; the switcher re-reads z-order via `EnumWindows` (top-to-bottom) as a tie-breaker); minimized handled by the "Minimized windows" option; `merge tabs` = one entry per process/app.
Which windows qualify: visible, top-level, non-tool (`WS_EX_TOOLWINDOW` excluded unless it has `WS_EX_APPWINDOW`), not cloaked by the shell itself (`DWMWA_CLOAKED` with `DWM_CLOAKED_SHELL`; cloaked by *other virtual desktop* are included unless "current desktop only"), has a title or icon, owner==null, not WinKnife's own overlay windows, not UWP `ApplicationFrameHost` shells without content (use `GetApplicationUserModelId` / resolve the hosted window via child `Windows.UI.Core.CoreWindow`).
**Geometry of the "Window previews" layout** (`SwitcherGrid`, scale s = preview-size scale):
- Card: width 288*s, height 214*s, padding 10, corner 14 (continuous), selected = white 14% fill + 2pt accent border; unselected clear. Thumbnail well = width-20, height = cardHeight-20-7-31 (title spacing 7, title block 31), radius 10 (bg text 5.5%), picture inset 5 radius 8; fallback app icon 80*s centered when no thumbnail; app badge icon 32*s at the picture's bottom-left; title 13pt (semibold when selected, medium otherwise) + subtitle 10.5pt medium; the title scrolls horizontally (marquee) when too long and selected/hovered; hover shows a close button top-right: `xmark.circle.fill` 19pt, white 72% -> 95% on hover over red (1.0,0.38,0.33).
- Panel: padding 20*s, spacing 12*s, corner 24 (continuous), `HUDBackdrop` + 1pt stroke text 12%. Usable area = 92% of the display's work-area width and 85% of its height (minus the search chip inset). columns = `fitByWidth = floor((usableWidth - 2*padding + spacing)/(cardW + spacing))`, limited by "Maximum columns" and balanced across rows (`wrappingColumnCount`); rows = ceil(count/columns); visible rows limited by height, extra rows scroll vertically (no sideways scroll).
- Search chip (when query non-empty or pinned): height 28 capsule at top, edge inset 12, contains magnifier glyph, query (11 semibold, max 180 wide), optional "S" pin keycap (monospaced 10 medium). `topInset = max(0, 12+28+8 - contentPadding)`.

- Fullscreen exclusive/DWM-cloaked windows have no live thumbnail: show app icon.

## A3. Dock clicks -> Taskbar clicks (`DockClickService`)
Behaviour (all via the same click interception): only a click on the taskbar button of the **active** app is handled; modifier clicks (Shift = new instance, Ctrl+Shift = admin, middle-click = new window) keep native behaviour; clicks closer than **0.25 s** to a handled click are ignored (double-click gap); after a handled click, the next click toggles from WinKnife's own record for **1.5 s** (`toggleIntentWindow`) instead of re-deriving from window state; the action commits on mouse-up, a press that moves more than **6 px** is a drag (button drag/reorder) and is replayed to the shell untouched.
- Minimize: minimize all unminimized windows of the app on the current desktop (batched; windows that remember z-order are captured front-to-back first); next click restores them **rearmost first** so the previously frontmost window animates in last and lands on top (no re-raise flicker; issue #357), then activates the app after the rear windows are up. Only restores what WinKnife minimized itself (`ownsMinimize`); windows minimized by the user keep native restore. Fullscreen windows cannot minimize (skip; they keep only "hide"). A sweep ~0.9 s after a minimize minimizes leftovers; ~0.35 s verify; ~0.6 s after restore re-asserts stragglers.
- Hide (macOS app-level hide has no Windows twin): implement as "minimize all windows of the app, including other desktops' windows, and remember them"; same toggle record.
- Cycle: click on the active app's button rotates to the next window of the app (front-to-back list of that app's un-minimized windows on the current desktop via z-order; a window on another desktop is never raised).
Windows mapping: `WH_MOUSE_LL` + the same UI Automation hit test as A2; swallow the down/up of handled clicks; `SetWindowPlacement`/`ShowWindowAsync(SW_MINIMIZE)`; `AttachThreadInput`+`SetForegroundWindow` to activate (activation from a hook thread needs the injected-Alt trick; macOS 14 comment has the same need). Windows 11 already minimizes a single-window app on click of its active button, so for single-window apps do nothing special.
Gap: WinKnife has no equivalent.

("fullScreen" = native full-screen toggle on macOS -> Windows: cover the whole monitor rect, no caption/borders via window style change is risky; implement as `F11`-like borderless: set `WS_POPUP`? Safer: maximize + hide taskbar not possible: implement as covering `rcMonitor` while keeping window style, restore on repeat), previous/next display = move keeping relative position/size scaled to the other work area).
- Size cycling: pressing Left/Right repeatedly cycles half -> 2/3 -> 1/3 (when `sideRepeatCyclesThirds`), or moves to the neighbouring display when more than one display; **tolerance 8 px** (`frameTolerance`) decides "same placement"; history per window for Restore; histories of dead windows are pruned only on explicit actions.
- Settle verification: after a placement the frame is re-read once the app commits (late resize) and re-applied if wrong ("settle" with a grace period); failures publish `failed` unless a newer action published.
- Directional ring (Shortcut + pointer layout): on shortcut key-down show a **glass ring** (circular HUD, ~320x320 in the mockup image: outer ring, 8 sectors + centre toggle icon) centred on the pointer; moving the pointer **>= 28 px** selects one of 8 sectors by angle (45° each, centred: right = Right half, up-right = Top right, up = Top half, up-left = Top left, left = Left half, down-left = Bottom left, down = Bottom half, down-right = Bottom right); the highlighted sector is filled accent (see image: blue wedge on the left = Left half); key auto-repeat must not trigger the manual centre action (`shouldApplyKeyboardManualOverride`); releasing the shortcut applies the selected placement; centre = maximize (and a keyboard "minimize" override while the ring is open). Esc cancels. Windows: layered topmost click-through window with per-pixel alpha (or WPF `AllowsTransparency`), pointer read via `GetCursorPos` in a 120 Hz `DispatcherTimer`, shortcut hold detection via the keyboard hook (key up). Window to place = the foreground window when the ring opened.
- Drag-to-edge snapping: while the same window has *visibly followed the pointer* toward a screen edge (title-bar drag detected through `WH_MOUSE_LL` + `GetGUIThreadInfo` `GUI_INMOVESIZE` or `EVENT_SYSTEM_MOVESIZESTART/END` WinEvents), within **12 px** of an edge/corner (`activationDistance`) and not crossing faster than **400 px/s** (`crossingSpeed`; pointer speed from a 50 ms ring of samples, min span 20 ms, "still" after 100 ms) a translucent preview rectangle (the target frame, rounded 8, accent 18% fill + 1.5pt accent border, DWM-composited topmost click-through window) follows; releasing snaps. A press with the chord held on a window takes custody and replays a plain click if the pointer never moves beyond **6 px** (`dragSlop`). Corner resize hit regions for the gesture: corners 12 px / edges 5 px; the centre of a window resizes from the nearest edge.
- Move/resize by dragging (modifier gesture): chord down + press inside a window = move (window origin += pointer delta); with Shift added = resize (nine regions: four corners resize two axes, four edges one axis, centre resizes from nearest edge; minimum size floor, re-anchor right/bottom or left/top after an app enforces a larger minimum); mouse right-button drag also resizes; the window is raised only once it becomes a real gesture (unless "Bring the dragged window to front" is on... raise happens on promote); frame writes are coalesced on a serial queue so a slow app never backs up (only the newest frame is pending); gesture ends wait for the last write.
- "Ignore apps" and "Pause" list: while a listed app is foreground, *no mouse or keyboard input is consumed or observed* by this feature.
### A6.3 Windows mapping
`RegisterHotKey` for shortcuts (or the keyboard hook so Win-based shortcuts work); work area `GetMonitorInfo(rcWork)`, DPI via `GetDpiForMonitor` (per-monitor v2 manifest); frame writes `SetWindowPos(SWP_NOZORDER|SWP_NOACTIVATE|SWP_ASYNCWINDOWPOS)` after `ShowWindow(SW_RESTORE)` if maximized, compensating the invisible resize border with `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)` minus `GetWindowRect` (7-8 px on Win10/11) so windows tile edge-to-edge; min/max size via `WM_GETMINMAXINFO` fallbacks (re-read after set); elevated windows -> admin card; skip windows that are `WS_EX_TOOLWINDOW`, desktop (`Progman`, `WorkerW`), taskbar (`Shell_TrayWnd`, `Shell_SecondaryTrayWnd`), or fullscreen (`SHQueryUserNotificationState`); UWP frames need `ApplicationFrameHost` resolution (window class `ApplicationFrameWindow` is the one to move). Windows Snap conflict as described. "Full Screen" action and "Stage Manager" caveats above.
### A6.4 Gap vs WinKnife (`WindowLayoutFeature.cs`)

### A7.2 Behaviour
- Eligibility: only apps that have *shown at least one real window since WinKnife began watching them* (apps launched window-less are never touched); a "real" window = visible, top-level, normal window of the process (or of a helper process drawing for it): not a tool window/popup/notification/UWP shell, not a sheet-like dialog. When the count of such windows drops to 0 and nothing else of the app is on screen (floating control bars, slideshow windows, file-open dialogs drawn by a separate process still count) the app is asked to quit. A window on another virtual desktop or a minimized one still counts as a window (keeps the app). A window the app merely *hid* (e.g. closed to tray) counts as no window.
- Timing: after a destroy/hide event, look at the app again at ~0.25 s and two more times (settle looks; macOS measured a 0.25 s fade); retries for apps whose window list is late; a refresh coalesced per run-loop turn on activation bursts; apps that launch asynchronously get an initial watch period.
- Quit = graceful: `WM_CLOSE` to every remaining top-level window of the process, including hidden ones (so apps run their normal exit path and "Save changes?" dialogs still appear), then wait. Windows fallback (decided): if the process still has no visible window and is still running after **5 s**, post `WM_CLOSE` then `WM_QUIT` (`PostThreadMessage`) to its UI threads and message-only windows; never `TerminateProcess` (Vorssaint has no force option).
- Exceptions also cover helper processes of the excepted app (same package/product, `ParentProcessId` chain, UWP package family).
- Skip: processes that are services, child processes whose parent is excepted, apps with an active download/upload? (n/a), RDP/VM viewers while connected (their guest windows look like zero windows).
Windows mapping: `SetWinEventHook(EVENT_OBJECT_CREATE/SHOW/HIDE/DESTROY, EVENT_SYSTEM_MINIMIZESTART/END)` out-of-context, `EnumWindows` + `GetWindowThreadProcessId` for per-process counts, `IsWindowVisible`, `DWMWA_CLOAKED`, `GetWindowLong(GWL_EXSTYLE)`. Tray detection (for "notification-area apps"): process owns a notification icon (enumerate `Shell_TrayWnd`->`TrayNotifyWnd`->`ToolbarWindow32` TB buttons via UI Automation, plus the overflow `NotifyIconOverflowWindow`) or has windows only from a `Shell_NotifyIcon` hidden window (class `...`), treat as tray app.
Gap: absent in WinKnife.

### E1.3 Engine and Windows mapping (`KeepAwakeManager`)
macOS: IOKit power assertions for the session; closed-lid mode = `pmset disablesleep` via a restricted sudoers rule installed once with the admin password (so toggling afterwards needs no password; removable); battery watchdog; automation evaluation (any/all); pause while locked; the preference-driven resume; recovery after a quit with sleep disabled; dim-on-lid-close saves the built-in brightness (never a stand-in 0) and restores it when the lid opens / session ends / next launch if owed (`LidDimmingSupport` decisions: close with armed option -> save reading (nil or 0 = already asleep: save nothing) then dim; open/disable/end/stale -> restore saved).
Windows:
- Session: `PowerCreateRequest` + `PowerSetRequest(PowerRequestSystemRequired)` (+ `PowerRequestDisplayRequired` unless "Allow the display to sleep"; optionally `PowerRequestAwayModeRequired`), visible in `powercfg /requests`; clear on end; fallback `SetThreadExecutionState(ES_CONTINUOUS|...)` from a dedicated long-lived thread. WinKnife's `KeepAwakeFeature` already has minutes choices + "also keep the display on"; extend as specified.
- **Lid closed**: set the lid-close action to "Do nothing": `powercfg /setacvalueindex SCHEME_CURRENT SUB_BUTTONS LIDACTION 0` and `/setdcvalueindex ... 0` then `powercfg /setactive SCHEME_CURRENT` (or `PowerWriteACValueIndex/DCValueIndex`+`PowerSetActiveScheme`); save the original AC/DC values and the active scheme GUID in a journal file **before** writing (recovery on next launch if WinKnife exited while overridden); restore on session end/app quit/uninstall. Try unelevated first; if access is denied, run one elevated helper (UAC "WinKnife needs permission to keep the PC going with the lid closed.") and optionally register a **scheduled task** (`schtasks /create /rl HIGHEST`, trigger on demand; the task runs `winknife.exe --lid on|off`) so later toggles need no prompt - the direct analogue of the sudoers rule ("Ready. Toggles without a password" -> "Ready. Toggles without asking for permission"; removing the rule = deleting the task; Settings > Advanced "Clear all permissions" deletes it). Detect "ready" by querying the task. Note Modern Standby laptops may still sleep on lid close if `LIDACTION` is overridden by policy.

# PART F - MONITOR SERVICES, ALERTS, CONNECTED DEVICES, FAN CONTROL

(The monitor panel/menu-bar/settings *pages* belong to another spec; this part defines the sampling services and alert rules they depend on. Hub group "System monitor": rows "CPU"/"Processor usage and temperature", "GPU"/"Graphics usage and temperature", "Memory"/"Memory use and pressure", "Network"/"Network speed and usage", "Disk"/"Disk space and activity", "Power"/"Battery, power and charging", "Connected Devices"/"Count connected external USB peripherals", "Fan Control"/"Control fans manually or with temperature curves while seeing live and target RPM".)

## F1. Sampling (`SystemMonitor`, `MonitorSamplingPolicy`)
- One background queue + one timer; **runs only while a full monitor surface is visible (panel/flyout) and/or a menu-bar (tray/readout) metric is enabled; otherwise the timer stops - zero idle cost**. Visible sections gate heavy samplers (GPU, network, power are not read while another section is on screen; the popover animation's GPU spike is ignored while GPU is pinned).
- Base interval setting `monitorIntervalSeconds`: **1 s / 2 s / 5 s** ("Update every": "1 second", "2 seconds", "5 seconds"), default **2**. Strides per metric (target seconds): **foreground** (surface visible): cpu, memory, network, disk, power, powerDraw, gpuUsage(+menuBar), temperature(+menuBar), fan(+menuBar) = 1 s (but never faster than the base interval), peripheralBattery 15 s, connectedDevices 2 s. **Background** (only tray/readout metrics): cpu, memory, network, powerDraw, gpuUsageMenuBar, temperatureMenuBar, fanSpeedMenuBar = 1 s; gpuUsage 10 s; fanSpeed 5 s; connectedDevices 10 s; power and temperature (battery/alerts) 15 s; disk 10 s (must stay well under `DiskSampler.maxGap` 15 s or the delta guard discards samples); peripheralBattery 60 s. `stride = ceil(target / interval)`; the timer wakes at the **GCD of the active strides** (so with only slow metrics it wakes rarely), ticks realigned to the grid after cadence changes (`alignedTick`); event-forced sampling (power source change, battery notification) bypasses the stride. Reading carried between reads keeps its original timestamp.
- Windows sources: CPU % = PDH `\Processor Information(_Total)\% Processor Utility` (fallback `GetSystemTimes`), per-core = `\Processor(n)\% Processor Time`; memory = `GlobalMemoryStatusEx` / `K32GetPerformanceInfo` (used, cached = standby+modified, commit/swap = page file, "pressure" = Normal/Caution/Critical derived from available % and commit ratio: Caution when available < 15 % or commit > 80 %, Critical when available < 8 % or commit > 90 % and hard-fault rate high); network = `GetIfTable2` byte deltas or PDH `\Network Interface(*)\Bytes Received/sec`, per-app via ETW `Microsoft-Windows-Kernel-Network`/`GetExtendedTcpTable` owner pids; disk = PDH `\PhysicalDisk(*)\Disk Read/Write Bytes/sec`, space = `GetDiskFreeSpaceEx`, SMART via `IOCTL_STORAGE_QUERY_PROPERTY`/WMI `MSStorageDriver_FailurePredictStatus` where available; GPU usage = PDH `\GPU Engine(*)\Utilization Percentage` (sum by engtype_3D/Compute), GPU temperature via vendor APIs (NVML/ADLX) when present; CPU temperature = WMI `MSAcpi_ThermalZoneTemperature` (root\wmi) or a ring-0 library (LibreHardwareMonitor) only if the user agrees (kernel driver prompt) - otherwise hide "Temperatures" (string `monitorUnavailable` "Sensors unavailable on this Mac" -> PC); power/battery = `GetSystemPowerStatus` + `IOCTL_BATTERY_QUERY_INFORMATION/QUERY_STATUS` (rate in mW, capacity, cycle count, health = FullChargedCapacity/DesignCapacity), battery time via `BatteryLifeTime`; peripheral battery (Bluetooth devices) via `BatteryLevel` GATT / `DEVPKEY_Bluetooth_Battery`; per-process usage via `GetProcessTimes`/ETW.

## F4. Fan Control (`FanControlService`, `FanControlHardware`, XPC helper) - **Windows-infeasible: mark "Not available on Windows"**
macOS feature: manual fan speed ("Fan speed" slider/"Manual" mode), temperature curves ("Curve" mode with sensor selection - Average SoC/Hottest SoC/Average CPU/Hottest CPU/Hottest GPU - and add/remove points on a temperature-vs-fan-speed graph), live and target RPM ("Current %d RPM"/"Target %d RPM"), a privileged login-item helper ("Allow fan control": "Allow Vorssaint in Login Items to use the protected fan controller."), safety rules (control returns to the system automatically if the app disconnects, the Mac sleeps, sensors fail or thermal pressure rises; "Resume after restart or sleep" option), strings `title` "Fan Control", `hubDescription` "Control fans manually or with temperature curves while seeing live and target RPM", `showInPanel` "Show Fan Control in the panel", `settingsCaption`, `noFans` "This Mac has no controllable fan.", `unsupported` "Fan control is not available on this Mac.", `alreadyControlled`, `failed`, `safetyCaption`, `safetyStopped`, `helperUnavailable`, etc.
Why it cannot be implemented on Windows: Windows exposes no OS-level fan API. Fans are driven by the embedded controller/BIOS (vendor WMI/ACPI methods differ per OEM - Lenovo/ASUS/HP/Dell each with proprietary, often signed-only, interfaces), or by Super-I/O chips accessible only through a ring-0 driver (LibreHardwareMonitor/PawnIO/OpenHardwareMonitor, which require loading a kernel driver, admin rights, HVCI/driver-blocklist compatibility, and vary by motherboard); writing the wrong register can brick fan control. There is no universal, safe, installable-without-kernel-driver way.
Decision for the WinKnife replica: (1) the **Fan Control hub entry is not shown on Windows** (or shown disabled with caption "Not available on Windows: fan speeds are controlled by your PC’s firmware." in the Features hub with no install button); (2) provide the closest *safe* equivalents: **(a) read-only fan RPM** where Windows exposes it (WMI `Win32_Fan` is almost never populated; LibreHardwareMonitor sensor if the user has it installed - no driver of our own) shown in the System monitor Temperatures/Fans row only when readable (`fanSpeed`/`fanSpeedMenuBar` sampling kinds stay, with 5 s stride); **(b) a "Cooling policy" quick control** = the processor *System cooling policy* power setting (`SUB_PROCESSOR`/`SYSCOOLPOL`: Active (fan first) vs Passive (throttle first)) via `powercfg /setacvalueindex SCHEME_CURRENT SUB_PROCESSOR SYSCOOLPOL 1|0` (+ DC) with strings "Cooling" / "Active" / "Passive"; and the Windows power mode (Best power efficiency / Balanced / Best performance via `PowerSetActiveOverlayScheme` GUIDs `961cc777-...`, `00000000-0000-0000-0000-000000000000`, `ded574b5-45a0-4f42-8737-46345c09c238`) as the user-visible lever for fan noise. Keep these two as optional additions, not as the Vorssaint Fan Control UI (no curves, no manual RPM).
Gap: absent in WinKnife (correctly).

# PART G - CROSS-CUTTING INFRASTRUCTURE AND SUMMARY

## G1. Shared infrastructure every feature above needs (build once)
1. **Input hook thread**: one dedicated thread with a message loop owning `WH_KEYBOARD_LL` and `WH_MOUSE_LL` (and `SetWinEventHook` out-of-context callbacks); callbacks do only arithmetic and post to a lock-free queue; each feature registers a "stage" (like WinKnife's `WheelPipeline`/`InputHooks`) with an ordered chain: *super key -> key debounce -> quit protection -> snippets -> switcher -> window layout hotkeys -> others*; mouse chain: *click debounce -> middle click -> mouse button shortcuts/side buttons -> window gesture/edge snap -> scroll stages (smooth/linear/invert/horizontal/zoom) -> focus follows mouse*. 3. **Journal/recovery store** for every system setting WinKnife touches (mouse acceleration, ExtendedUIHoverTime, active window tracking, lid action, SDR white level, taskbar auto-hide, Bluetooth radio state, desktop order): write the previous value *before* changing, restore on feature off / app exit / next launch if a journal exists; Settings > Advanced "Clear all permissions" and uninstall restore everything (macOS equivalent: `SelfUninstall`, `Tools/uninstall.sh`).

5. **Overlay windows helper**: topmost no-activate click-through/hit-testable panels with Acrylic/Mica, per-monitor DPI, all-desktops visibility (0.4), light/dark theme.

7. **Per-feature enable model**: Vorssaint's "feature installed" (hub) vs "toggle on" distinction: a feature that is installed shows its page/card; its service only runs when its own toggle is on (nothing alive otherwise); uninstalling removes it from the UI and stops loading it.
